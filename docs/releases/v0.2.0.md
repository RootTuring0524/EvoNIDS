# EvoNIDS v0.2.0 — 运营内核发布说明

- 版本：0.2.0
- 日期：2026-09-28
- 范围：Phase 1–7 的生产化改造（工程与安全基线 → 集群与发布准备）
- 兼容性：数据库需要 `alembic upgrade head`（当前 head `20260909_0013`）；API 新增端点，旧端点行为保持不变

## 1. 本版本解决的核心问题

| 问题（v0.1.0） | v0.1.1 的处置 |
| --- | --- |
| 在线检测不存在，`Flow.verdict` 恒为 `benign` | 采集时内联双通道检测，逐通道写入 `detection_signals`，每次融合写入可解释的 `risk_assessments`；默认 `shadow`（只记录不告警） |
| 训练/推理特征不一致（CICIDS 42 列 vs EVE 可观测字段） | 统一 `flow-online-v1` 契约，离线投影与在线构造共用同一公式并有等价性测试；已训练契约模型并优先选用（零插补） |
| 结论是自由文本，无法回溯证据 | 调查结论拆分为 Claim，逐条引用白名单内 `evidence_id`；越界引用保存为 rejected 并记录原因 |
| 检索是关键词回退（`vector_score` 恒 0） | BM25 + 向量混合检索、信任/租户/过期过滤、注入隔离、可复现检索快照 |
| 规则只有进程内谓词回放 | 规范化 Rule IR → 确定性 Suricata 编译 → 真实沙箱语法校验与标注 PCAP 回放（无 Suricata 时记为 `blocked`） |
| 规则 `confirmed → deployed` 一步跳转 | 传感器分组 + 灰度/提升/回滚，前置条件是存在通过的沙箱运行；全过程审计 |
| 共享 admin token、无传感器身份 | scoped 哈希 API Key（admin/sensor/analyst）、传感器注册与心跳、时钟偏差与数据质量指标、`Authorization: Bearer` 与 scoped header 双支持 |
| 无采集端可靠性 | 采集器磁盘 spool（原子落盘 + 确认后删除）、幂等批次号、指数退避、dead-letter、限速、gzip |
| 无速率限制/安全响应头 | CSP/X-Frame-Options/nosniff/Referrer-Policy/Permissions-Policy/Cache-Control，生产启用 HSTS；写操作按主体限流 + JSON 体积上限 |
| 无模型漂移观测 | PSI/KS 特征漂移 + 预测漂移，未测量保持未测量 |

## 4. 真实测量结果（本机，Windows 10，16 逻辑 CPU，Python 3.11.1，无 GPU）

- 数据集：`DS-CIC-2017-PCAP-FULL`，2,120,625 行，SHA-256 `f9ff72b9768e38637c401d287327173f1408c9fbdcacb8a8b82f472abcac5fec`
- 在线契约模型训练（时间外切分，训练窗口结束 2017-07-07 14:48，测试窗口从 2017-07-07 18:56 开始）：
  - 基线（HGB，16 特征）：OvR ROC-AUC 0.9724、PR-AUC 0.9387、accuracy 0.4424、macro-F1 0.0621
  - AutoEncoder：ROC-AUC 0.9079、AP 0.8734、阈值 0.0341（验证集 95 分位）、阈值处召回 38.8%、正常流误报 6.33%
- 既有 CICIDS 42 特征模型（同域随机切分）：基线 macro-F1 0.8883；AE recall 27.48% @5% FPR、AUROC 0.9042
- 采集器与网关单元测试、限流、安全响应头、迁移循环、OpenAPI 快照：见 `backend/tests/`（210 项后端测试通过）

**明确未测量**：真实 Suricata 语法校验与 PCAP 回放指标、生产吞吐/延迟（仅有本机 smoke）、跨数据集（UNSW-NB15 等）泛化、真实 LLM 供应商的延迟/成本/Token、哈希嵌入的语义检索质量、Helm/Compose 的实际部署验证。

## 5. 已知限制（不得对外宣称已解决）

1. `shadow` 是默认检测模式；`enabled` 需要在线契约模型通过 ADR-0009 评估并由运维显式开启。
2. 在线契约基线在时间外窗口的 macro-F1 仅 0.062，**不能**作为生产能力证明。
3. 本机无 Suricata 二进制与标注 PCAP 语料，规则真实验证记录为 `blocked`。
4. 限流是进程内的，多副本部署下每个副本各自计数。
5. NATS JetStream / ClickHouse / MinIO 未引入，触发条件见 ADR-0008。
6. 开发库曾出现 `create_all` 与 Alembic 版本漂移（sensors 缺列导致 500）；修复方式与教训见 `docs/deployment.md`，生产必须以迁移为唯一建表路径。

## 6. 升级步骤

1. 备份：`scripts/backup/backup.sh`（或 `backup.ps1`）。
2. 停止写入（或进入维护窗口），执行 `alembic upgrade head`。
3. 设置新增环境变量（见 `.env.example`）：`EVONIDS_DETECTION_MODE`、`EVONIDS_LLM_PROVIDER`、`EVONIDS_EMBEDDING_PROVIDER`、`EVONIDS_RATE_LIMIT_*`。
4. 重启 API 与 Web；确认 `GET /api/v1/health`、`GET /api/v1/readiness`、`GET /api/v1/detections/status`。
5. 如需在线告警：先训练在线契约模型（`scripts/train_online_contract_models.py --register`），再把模型发布状态设为 `active`，最后切换 `EVONIDS_DETECTION_MODE=enabled`。

## 7. 回滚

- 配置级：`EVONIDS_DETECTION_MODE=disabled`、`EVONIDS_LLM_PROVIDER=disabled` 可立即停用新能力，无需迁移。
- 模型级：`POST /models/rollback`（需 ≥10 字符原因）。
- 规则级：`POST /rule-governance/deployments/{id}/rollback`。
- 数据库级：`alembic downgrade 20260909_0010`；回滚前用 `scripts/backup/backup.sh` 归档。

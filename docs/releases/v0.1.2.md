# EvoNIDS v0.1.2 — 治理与可复现性补丁发布说明

- 版本：0.1.2
- 日期：2026-11-17
- 范围：规则证据链闭合、摄取路径纳入审计、Flow Transformer 异常通道真正可用、E01–E10 实验登记表
- 兼容性：**无数据库迁移**（未新增/修改表结构）；API 行为变化仅一处收紧（候选规则的 `evidence_ids` 现在会被校验）
- 前置版本：0.1.1（运营内核）

## 1. 本版解决的问题

| 问题（v0.1.1 遗留） | v0.1.2 的处置 |
| --- | --- |
| 候选规则可以引用**不存在的证据 ID**：`POST /rules` 只检查 `evidence_ids` 非空，编造的标识符会被写入不可变版本记录（实测：虚构的 `EV-KNOWLEDGE-001` 曾被接受） | 现在逐个校验：证据必须**存在**、`allowed=true`、`prompt_injection_risk=none`，否则返回 `422` 并在错误信息中点名。测试覆盖接受/不存在/被隔离三种情形，并断言失败请求不会留下规则 |
| **摄取路径不写审计**：EVE 导入是系统唯一的数据面写入，却只在 `Sensor` 行记计数，事后无法追溯被投毒或畸形的导入 | HTTP 导入与采集器批次两条路径都写一条 `ingestion.eve_batch` 审计事件（通道、载荷大小、accepted/created/duplicate/rejected、检测模式、是否降级），进入与其他写操作相同的哈希审计链 |
| `--task anomaly` **只记录不生效**：标志被接受并写进产物元数据，但实际仍执行监督分类路径 | 异常任务现在只做 MFM 预训练，在**验证集**正常重建误差上按 `--target-fpr` 冻结阈值，并报告该阈值下的 AUROC/AUPRC/攻击召回/精确率/F1/实测正常误报率/逐类检出率。未预训练时直接报错，而不是产出无意义的模型 |
| 没有统一的**实验登记表**：实验脚本零散，论文表格只能靠记忆拼装 | 新增 `backend/scripts/run_experiments.py`：登记 E01–E10，按本机环境探测可运行性，未运行的实验标注 `ready` 或 `blocked: needs …` 并给出确切命令；`--run` 可执行 Transformer 家族（E03–E05）并把实测指标连同**产出该指标的数据集**一起记录。生成物是 `docs/experiments.md` |

## 2. 数据库迁移

无。本版未新增或修改任何表结构，`alembic upgrade head` 仍停在既有 head。

## 3. API 行为变化

| 端点 | 变化 |
| --- | --- |
| `POST /api/v1/rules` | `evidence_ids` 现在必须能解析到真实、allowed、无注入风险的证据，否则 `422`。此前只校验非空 |
| `POST /api/v1/ingestion/eve` | 响应不变；额外写入一条审计事件（异步可见于 `/api/v1/audit`） |

## 6. 已知限制（不得对外宣称已解决）

1. 检测默认仍是 **shadow**；`enabled` 需要在线契约模型通过 ADR-0009 评估并由运维显式开启。
2. 在线契约基线的时间外 macro-F1 仍为 **0.062**，不能作为生产能力证明。
3. **Flow Transformer 权重未训练**：代码、掩码目标、消融 CLI、单元测试与产物格式已就绪，但本版不含任何该架构的实测指标。
4. 本机无 Suricata 二进制与标注 PCAP，规则真实验证记录仍为 `blocked`（实验登记表中 E09 明确标注）。
5. RAG 默认嵌入是哈希词法嵌入；真实嵌入/向量检索需要 provider key（E10 标注为 blocked）。
6. `docs/experiments.md` 当前为 `measured=0 of 10`——这是真实状态，不是遗漏。
7. 无真实流量验证：所有数字仍来自 CICIDS2017 派生数据集。

## 8. 回滚

本版无 schema 变更，回滚只需把应用回退到 v0.1.1 的镜像/提交；`ingestion.eve_batch` 审计事件与证据校验都属于新增行为，旧版本读取不会失败。已写入的审计事件与规则版本不需要清理。

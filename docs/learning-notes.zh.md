# Root的NIDS系统
## 项目题目
基于自监督深度流量表征与大模型规则进化的自适应入侵检测系统设计与实现
## 项目一句话说明
　　本项目要做的是一个智能入侵检测系统。系统通过深度学习模型分析网络流量，发现已知攻击和未知异常；再结合 RAG 检索安全知识，由 LLM-Agent 生成或修复检测规则，并通过验证机制让规则库不断进化。

# Day1
## 1、IDS、NIDS、HIDS 分别是什么？
| 类型 | 全称 | 检测对象 | 数据来源 | 适合检测什么 |
|---|---|---|---|---|
| IDS | Intrusion Detection System | 入侵行为总称 | 网络、主机、日志等 | 攻击、入侵、异常行为 |
| NIDS | Network-based IDS | 网络流量 | 数据包、NetFlow、连接记录 | 扫描、DDoS、暴力破解、C2、异常外连 |
| HIDS | Host-based IDS | 主机内部行为 | 系统日志、进程、文件、登录记录 | 异常登录、文件篡改、权限提升、恶意进程 |

　　本项目主要属于 NIDS，因为它主要分析网络流量特征，而不是分析某台主机内部的日志、进程或文件变化。

## 2、特征检测和异常检测有什么区别
| 对比项 | 特征检测/签名检测 | 异常检测 |
|---|---|---|
| 核心思想 | 根据已知攻击规则进行匹配 | 学习正常行为，发现偏离正常的行为 |
| 检测对象 | 已知攻击 | 未知异常、未知攻击、变种攻击 |
| 优点 | 准确、可解释、误报较低 | 能发现未知异常，不完全依赖规则 |
| 缺点 | 对未知攻击能力弱，需要维护规则库 | 误报较高，解释性较差 |
| 例子 | Snort/Suricata 规则、端口扫描规则 | AutoEncoder、Isolation Forest、异常分数 |

简单理解：
　　特征检测是"我知道坏人长什么样，所以我去匹配他"。异常检测是"我先知道正常人什么样，然后发现谁不正常"。

## 3、为什么本项目要把特征检测和异常检测结合起来？
　　因为只靠特征检测，系统只能识别已经见过的攻击，对未知攻击和变种攻击能力弱。
　　只靠异常检测，虽然可能发现未知异常，但误报比较高，而且不容易解释。
所以本项目的思路是：

1. 深度学习模型先发现异常
2. RAG-Agent 分析异常原因
3. 生成或修复检测规则
4. 系统验证规则
5. 规则通过后加入规则库

　　这样 IDS 就可以从异常中沉淀新的检测规则。

## 4、本项目的核心闭环是什么？
本项目的核心闭环是：

1. 网络流量数据
2. 自监督深度模型学习流量表征
3. Flow Transformer 识别已知攻击
4. AutoEncoder 发现未知异常
5. 系统提取异常攻击画像
6. RAG 检索安全知识、历史规则和规则样例
7. LLM-Agent 判断是新攻击还是旧规则变体
8. 生成新规则或修复旧规则
9. 历史流量回放验证规则命中率和误报率
10. 验证通过后规则入库
11. 后续检测时规则库直接参与告警

## 总结
　　本项目是一个 NIDS 项目，主要检测网络流量中的攻击行为和异常行为。它不是漏洞挖掘系统，也不是防火墙，而是一个智能入侵检测系统。
　　它的核心创新不是让大模型解释告警，而是让深度学习模型发现异常，再让 RAG-Agent 把异常转化为可验证、可沉淀、可进化的检测规则。

# Day2
## 1、DoS 攻击是什么？
　　DoS（Denial of Service，拒绝服务攻击）是攻击者通过持续发送大量请求，或者利用系统缺陷消耗目标服务器的带宽、CPU、内存和连接资源，使正常用户无法访问服务。
　　典型场景包括：单台攻击主机持续向网站、服务器或网络设备发送大量请求。
流量上可能出现的异常：
- 单个源 IP 在短时间内发送大量请求。
- 请求频率明显高于正常水平。
- 大量连接长期占用但不完成通信。
- 目标服务器的入站流量突然增加。
- SYN 包、UDP 包或其他特定类型数据包异常增多。
　　IDS 可以通过请求频率、连接数量、数据包类型、流量大小和时间窗口等特征，识别 DoS 攻击的异常流量模式。

## 2、DDoS 攻击是什么？
　　DDoS（Distributed Denial of Service，分布式拒绝服务攻击）是由大量被控制的设备同时向同一个目标发送请求，使目标服务器或网络资源耗尽。
DDoS 和 DoS 的主要区别是：
- DoS 通常来自单个或少量攻击源。
- DDoS 来自大量分布式攻击源，攻击规模更大，也更难通过封禁单个 IP 阻止。
　　典型场景包括：大量僵尸主机同时访问某个网站、接口或服务器，导致服务无法正常响应。
流量上可能出现的异常：
- 短时间内出现大量不同源 IP。
- 多个源 IP 同时访问同一个目标。
- 目标端口收到大量重复请求。
- 总流量、数据包数量和连接数量突然增加。
- 请求来源分散，但行为模式高度相似。
　　IDS 可以通过源 IP 数量、总流量、连接频率、目标集中程度和流量突增情况检测 DDoS 攻击。

## 3、Port Scan 端口扫描是什么？
　　Port Scan，即端口扫描，是攻击者向目标主机的多个端口发送探测请求，判断哪些端口处于开放状态，以及目标主机运行了哪些网络服务。
　　攻击者进行端口扫描的主要目的是收集目标信息，为后续漏洞利用、暴力破解或入侵做准备。
　　端口扫描通常属于攻击前期的侦察行为，它本身不一定已经完成入侵。
流量上可能出现的异常：
- 同一个源 IP 在短时间内访问大量不同端口。
- 单次连接持续时间较短。
- 大量连接没有完成完整通信。
- SYN 包数量较多，但成功建立的连接较少。
- 目标端口连续变化或呈规律性变化。
　　IDS 可以根据单位时间内访问的端口数量、连接失败比例、SYN 包比例和连接持续时间识别端口扫描。

## 4、Brute Force 暴力破解是什么？
　　Brute Force，即暴力破解，是攻击者不断尝试不同的用户名和密码组合，直到获得正确的登录凭据。
暴力破解通常针对：
- SSH 服务
- FTP 服务
- 远程桌面服务
- 邮箱登录
- 网站登录页面
- 数据库服务
流量上可能出现的异常：
- 同一源 IP 短时间内发起大量登录请求。
- 同一账号出现大量登录失败记录。
- 多个账号被同一个源 IP 反复尝试。
- 请求目标端口较固定，例如 SSH 的 22 端口。
- 登录请求的时间间隔和数据包大小较为相似。
　　IDS 可以通过登录请求次数、失败频率、源 IP、目标端口和访问时间规律检测暴力破解行为。

## 5、Botnet 僵尸网络是什么？
　　Botnet，即僵尸网络，是由攻击者控制的大量受感染主机组成的网络。被控制的主机被称为僵尸主机或 Bot。
　　一台主机可能因为恶意程序、漏洞利用、钓鱼文件或弱口令入侵而成为僵尸主机。
　　攻击者通常通过 C2 服务器向僵尸主机发送命令。C2 是 Command and Control，即命令与控制，主要负责控制受感染主机执行攻击、下载恶意程序、窃取数据或发送垃圾信息。
Botnet 流量可能出现的异常：
- 主机周期性连接某个固定服务器或域名。
- 大量主机连接同一个外部地址。
- 主机在非正常时间主动向外建立连接。
- 数据包较小，但通信具有固定时间间隔。
- 出现异常 DNS 查询、加密通信或陌生端口通信。
- 主机突然参与 DDoS、扫描或垃圾信息发送。
　　IDS 可以通过异常外连、周期性通信、相似主机行为、可疑域名、连接关系和流量时间规律检测 Botnet 或 C2 通信。

## 6、这五类攻击有什么区别？
| 攻击类型 | 主要目的 | 典型流量特点 |
|---|---|---|
| DoS | 让目标服务不可用 | 单个攻击源产生大量请求 |
| DDoS | 通过分布式流量压垮目标 | 大量源 IP 同时访问同一目标 |
| Port Scan | 探测开放端口和服务 | 同一源 IP 短时间访问多个端口 |
| Brute Force | 猜测账号和密码 | 大量重复登录请求或登录失败 |
| Botnet | 控制大量受感染主机 | 周期性外连、C2 通信、多个主机行为相似 |

　　DoS、DDoS 和暴力破解通常既可以通过已知规则检测，也可以通过异常流量检测。
　　Port Scan 可以通过单位时间内访问端口数量等规则检测，也可以通过连接行为异常进行检测。
　　Botnet 的通信方式可能不断变化，因此除了特征检测外，还需要结合异常检测、通信关系和时间序列特征进行分析。

# Day3
## 1、为什么 IDS 项目需要数据集？
　　IDS 需要通过数据集学习正常流量和攻击流量之间的区别。
数据集在本项目中主要有以下作用：
- 为深度学习模型提供训练数据。
- 帮助模型学习不同攻击的流量特征。
- 使用测试数据检验模型的检测效果。
- 计算准确率、召回率、F1 值和误报率等指标。
- 为后续规则生成和历史流量回放提供数据。
简单理解：
- Feature 是模型看到的条件。
- Label 是这条数据的正确答案。
- 模型训练就是学习 Feature 和 Label 之间的关系。

## 2、一条网络流量记录是什么？
　　一条网络流量记录通常表示两台主机之间的一次通信过程，而不只是一个单独的数据包。
　　一次通信过程中可能会产生多个数据包。流量特征提取工具会把属于同一次通信的数据包进行统计，形成一条 Flow 流量记录。
一条流量记录通常包含：
- 通信双方的地址和端口。
- 使用的网络协议。
- 通信持续时间。
- 前向和后向的数据包数量。
- 前向和后向的字节数量。
- TCP 标志位。
- 流量对应的真实类别。
例如：

| 协议 | 源端口 | 目的端口 | 持续时间 | 包数量 | 字节数 | 标签 |
|---|---|---|---|---|---|---|
| TCP | 51023 | 80 | 2.4 秒 | 18 | 12480 | Benign |
| TCP | 42317 | 22 | 0.3 秒 | 120 | 8400 | Brute Force |

　　第一条可能是一次正常的网页访问。
　　第二条可能是某个攻击者在短时间内频繁访问 SSH 服务，因此被标记为暴力破解流量。

## 3、正常流量和攻击流量分别是什么？
　　正常流量是用户正常使用网络服务时产生的通信。
例如：
- 浏览网页。
- 登录正常系统。
- 下载文件。
- 发送邮件。
- 访问数据库。
- 使用即时通信软件。
　　攻击流量是攻击者实施恶意行为时产生的通信。
例如：
- DoS 和 DDoS。
- 端口扫描。
- 暴力破解。
- Botnet 和 C2 通信。
- Web 攻击。
- 漏洞利用。
- 异常数据外传。
　　正常流量和攻击流量可能使用相同的协议和端口，因此不能只根据一个字段判断攻击，需要结合多个流量特征共同分析。

## 4、Feature 和 Label 分别是什么？
| 概念 | 中文含义 | 作用 |
|---|---|---|
| Feature | 特征 | 描述一条网络流量的行为 |
| Label | 标签 | 表示该流量的真实类别 |

Feature 的例子包括：
- 协议。
- 源端口。
- 目的端口。
- 流量持续时间。
- 数据包数量。
- 字节数量。
- TCP 标志位。
- 每秒数据包数量。
- 每秒传输字节数量。
Label 的例子包括：
- Benign：正常流量。
- DDoS：分布式拒绝服务攻击。
- PortScan：端口扫描。
- Brute Force：暴力破解。
- Bot：僵尸网络流量。
在监督学习中：
- Feature 是模型的输入。
- Label 是模型需要学习的正确答案。
- 模型通过大量 Feature 和 Label 的对应关系学习如何判断流量类型。

## 5、常见网络流量字段表示什么？
| 字段 | 含义 | 对 IDS 的作用 |
|---|---|---|
| Protocol | 通信使用的协议，如 TCP、UDP、ICMP | 判断攻击所使用的通信方式 |
| Source Port | 发起通信一方使用的端口 | 辅助分析流量来源 |
| Destination Port | 目标服务使用的端口 | 判断攻击针对的服务 |
| Duration | 一次流量持续的时间 | 识别短时扫描或异常长连接 |
| Packets | 通信中的数据包数量 | 判断请求是否异常密集 |
| Bytes | 通信中传输的字节数量 | 判断是否存在流量突增或数据外传 |
| Forward Flow | 从源主机发往目标主机的流量 | 分析请求方向的行为 |
| Backward Flow | 从目标主机返回源主机的流量 | 分析响应方向的行为 |
| TCP Flags | SYN、ACK、FIN、RST 等标志位 | 识别扫描、SYN Flood 和异常连接 |
| Label | 正常流量或攻击类别 | 用于模型训练和测试 |

　　单独一个字段通常不能直接判断攻击，需要结合多个字段共同分析。
例如，端口扫描可能同时具有以下特征：
- 同一个源地址在短时间内发起大量连接。
- 访问的目的端口不断变化。
- 每次连接持续时间较短。
- SYN 包数量较多。
- 成功建立的连接较少。

## 6、CICIDS2017 是什么？
　　CICIDS2017 是网络入侵检测研究中常用的数据集之一，包含正常网络流量和多种常见攻击流量。
CICIDS2017 中常见的攻击包括：
- Brute Force。
- DoS。
- DDoS。
- Port Scan。
- Botnet。
- Web Attack。
- Infiltration。
- Heartbleed。
常见流量特征包括：
- 目的端口。
- 流量持续时间。
- 前向和后向数据包数量。
- 前向和后向字节数量。
- 每秒数据包数量。
- 每秒字节数量。
- 数据包长度。
- TCP 标志位。
- 流量标签。
CICIDS2017 在本项目中的用途：
- 训练 Flow Transformer 识别已知攻击。
- 训练 AutoEncoder 学习正常流量模式。
- 分析不同攻击的流量特征。
- 模拟未知攻击检测实验。
- 验证生成规则的命中率和误报率。

## 7、UNSW-NB15 是什么？
　　UNSW-NB15 是另一个常用的网络入侵检测数据集，包含正常流量和多种现代网络攻击。
UNSW-NB15 中的主要攻击类别包括：
- Fuzzers。
- Analysis。
- Backdoors。
- DoS。
- Exploits。
- Generic。
- Reconnaissance。
- Shellcode。
- Worms。
常见字段包括：
- 网络协议。
- 源端口和目的端口。
- 服务类型。
- 连接状态。
- 通信持续时间。
- 源端和目的端的数据包数量。
- 源端和目的端的字节数量。
- 攻击类别。
- 正常或攻击标签。
UNSW-NB15 在本项目中的用途：
- 与 CICIDS2017 进行对比实验。
- 测试模型在不同数据集上的表现。
- 验证模型的泛化能力。
- 补充 CICIDS2017 没有覆盖的攻击类别。
- 测试模型面对不同流量分布时的适应能力。

## 8、CICIDS2017 和 UNSW-NB15 有什么区别？
| 数据集名称 | 包含的主要攻击类型 | 常见字段 | 后续在项目中的用途 |
|---|---|---|---|
| CICIDS2017 | DDoS、DoS、Port Scan、Brute Force、Botnet、Web Attack、Infiltration 等 | 协议、端口、持续时间、包数量、字节数、TCP 标志位等 | 作为主要数据集，训练 Flow Transformer 和 AutoEncoder，并验证生成规则 |
| UNSW-NB15 | Fuzzers、Backdoors、DoS、Exploits、Generic、Reconnaissance、Shellcode、Worms 等 | 协议、端口、服务、连接状态、持续时间、包数量、字节数等 | 作为对比数据集，测试模型的泛化能力和跨数据集效果 |

　　项目初期可以先使用 CICIDS2017 跑通完整流程。
　　等深度学习检测、RAG-Agent 和规则验证模块完成以后，再加入 UNSW-NB15 进行对比实验。

## 9、本项目将怎样使用数据集？
本项目使用数据集的大致流程是：
```text
下载数据集
→ 查看字段和标签
→ 清理缺失值、重复值和无限值
→ 编码协议和攻击类别
→ 对数值特征进行标准化
→ 划分训练集、验证集和测试集
→ 使用 Flow Transformer 识别已知攻击
→ 使用 AutoEncoder 发现未知异常
→ 从异常流量中提取攻击画像
→ RAG 检索相关安全知识和历史规则
→ LLM-Agent 生成或修复检测规则
→ 使用历史流量验证规则的命中率和误报率
```
